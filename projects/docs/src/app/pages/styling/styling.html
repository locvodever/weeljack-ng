Styling

Style a wj-* component from its host, from the --wj-* variables, or, as a last resort, through the Optimus parts underneath.

    @for (section of sections; track section.id) {
  • {{ section.title }}
    • }

Host class and style

class and style go on the wj-* host as plain attributes. The host renders a real box, never display: contents, so they style something you can see: an inline-flex box for a button-like control, a block for a panel, an overlay or a data component.

CSS variables

The primitive and semantic --wj-* variables are public. Override one on :root and every component reads it through its var() chain. All WeeljackNg styles sit in one CSS layer, wj, so your unlayered CSS always wins, and an app that uses other layers declares the order once. The Theming page lists every variable and shows the layer order.

The pt escape hatch

Every wrapper has one pt input. It is forwarded verbatim to the pass-through of the Optimus component underneath, and typed Wj<Name>Pt, such as WjButtonPt. It reaches every part, nested ones included, and takes classes, styles and attributes.

  • Your pt merges over the wrapper's own. Where a wrapper sets a part's attributes itself, such as ARIA names, its component page says which side wins.
  • Its part names track the installed Optimus minor, so pt is outside the stable API. Part changes ship only in the release that takes a new Optimus minor, under their own changelog heading, and are not breaking.

What does not exist

These Optimus names have no WeeljackNg counterpart:

  • styleClass
  • dt
  • unstyled
  • ptOptions
  • A global pt

The own components, wj-sheet and wj-field, have no pt either. Style them with host class and style and their documented --wj-* variables.

A wj-button with a host class, which draws a dashed frame around the host's box, and a pt part, which sets the style of the button's label.
