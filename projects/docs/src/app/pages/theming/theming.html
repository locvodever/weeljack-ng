Options

provideWeeljack reads its options once, at bootstrap. Only primary and surface can change later, through WjTheme (below).

primary and surface

primary takes a #rrggbb base colour, which becomes step 500 of a generated 50 to 950 scale, a palette name such as '{indigo}', or a full scale (WjColorScale). Left out, the primary is the default ink.

A palette name becomes that palette's own scale. In the light scheme, its primary colour takes the lightest step that passes AA with white text: indigo uses step 600 and sky uses step 700, with hover and active one and two steps darker. A hex base or a full scale is used exactly as you give it.

surface takes the same forms for the page, card and border colours, or { light, dark } to set each scheme. Left out, it is zinc, and surface.0 stays white unless your scale sets a 0 step.

darkMode

'off' is the default and always renders the light scheme. 'system' follows prefers-color-scheme. 'class' renders dark while .wj-dark is on <html>.

translation

The strings WeeljackNg renders itself, such as accessible names and empty messages. Pass a complete language from weeljack-ng/locale or a partial object; see Language.

Change colours at runtime

WjTheme, from weeljack-ng/theme, changes primary and surface after bootstrap, in the same forms. The result equals bootstrapping with those values, and reset() goes back to what provideWeeljack set.

  • A string that is not a colour logs WJ0200 and changes nothing. A hex base or scale under AA contrast applies and logs WJ0010, once for each different colour.
  • On the server the calls do nothing: the server renders the bootstrap theme.
  • Dark mode, radius and fonts are still read once, at bootstrap. An app that never imports weeljack-ng/theme ships none of it.

The default look

The default is "Noir on zinc": an ink primary, zinc surfaces, 44 px controls and one 2 px focus ring. Both panes show the same buttons. The first follows the page, so the Dark mode toggle in the header switches it. The second is always dark, because .wj-dark scopes the dark variables to its own subtree.

The brand warning

A custom primary or surface is checked on four pairs, in the light scheme and, unless darkMode is 'off', the dark one:

  • --wj-button-primary-color on --wj-button-primary-background: 4.5:1.
  • --wj-focus-ring-color on the card surface: 3:1.
  • --wj-form-field-border-color on --wj-form-field-background: 3:1.
  • --wj-form-field-placeholder-color on --wj-form-field-background: 4.5:1.

In development mode, a pair under its ratio logs WJ0010, naming each failing pair and scheme. It reads preset values only, so it never throws and never stops bootstrap. A palette name passes by construction, so the check matters for a hex base or a full scale. Fix a failure with a darker step of the scale, or override the named variables.

CSS variables

The primitive and semantic variables below are public. The component-level variables, such as --wj-button-primary-background, are an escape hatch and are not listed. Values are those of the default look.

To override one, set it on :root, with the dark value under .wj-dark or, for darkMode: 'system', inside @media (prefers-color-scheme: dark). Components read these through var() chains, so the change flows through.

Language

weeljack-ng/locale ships complete en and vi objects for translation. English is the default, and translation is merged over it one level deep, so a partial object keeps every other English string. The same goes for the aria and wj groups, where wj holds WeeljackNg's own strings, such as showPassword and hidePassword.

When you build on a shipped language, spread aria on its own. Otherwise your aria group replaces the language's whole group, and the missing names fall back to English.

WeeljackNg sets neither LOCALE_ID nor <html lang>. Both stay yours, and the language is read once like every other option.
