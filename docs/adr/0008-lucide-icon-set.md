# Lucide icon set

Status: accepted

WeeljackNg ships its own icon set as typed SVG data that `wj-icon` draws, in one own entry, `weeljack-ng/icon`: a `WjIconDef` is a name, a viewBox and a list of `[tag, attributes]` nodes over seven SVG shapes, rendered through fixed template bindings with no `innerHTML` and no sanitizer bypass, so it renders on the server and tree-shakes to the icons an app imports. The 80 starter icons are generated by `scripts/generate-icons.mjs` from a pinned, exact `lucide` devDependency and the checked-in list `icon-set.json`, and a `--check` mode in `npm run build` fails on drift in the generated file or in the licence text. **This amends ADR 0007**, whose rule copies code only from Optimus or PrimeNG v21 and earlier: it now also allows Lucide icon data (ISC, with the portions Lucide derived from Feather under MIT) — data, not component code — under the same attribution scheme. The generated file opens with the SPDX line, source package and version, the licence's copyright lines and a `Modifications Copyright` line; `THIRD-PARTY-NOTICES.md`, shipped in the npm tarball, carries Lucide's full licence text; and the docs describe the source as a description (an independent open-source icon project, not affiliated), never as branding. ADR 0007 itself is not edited.

## Considered Options

- **Wrap the OpenNG icon font (`@openng/icons`, `pi pi-*`).** Rejected: it ships whole behind a global CSS import, exposes Optimus naming against ADR 0001, cannot be tree-shaken, and shows nothing until the font loads.
- **`lucide-static`.** Rejected: it ships SVG files and fonts, so the generator would have to parse markup. `lucide` ships each icon as an ES module whose default export is already the `[tag, attributes][]` list `WjIconDef` uses, so the generator reads data.
- **Draw a set by hand.** Rejected: the cost is high and there is no upstream to track.

Provenance: Loc's decision, 2026-11-22 (Own SVG icon set).
